Issue 004: Surprise Rule Flexibility — Config-Driven Adaptation
================================================================

Date  : 2026-07-30
Scope: Entire codebase — config, dynamics, main.py, ESP32 L298N

========================================================================
WHY THIS EXISTS
========================================================================

WRO 2026 introduces Surprise Rules (Rule 6): a small change announced
on competition day that forces teams to re-program their robot (e.g.
swap pillar colours, force drive direction, narrow the track).

The rubric awards +6 points for "Systems Thinking" if your code can
adapt to a Surprise Rule by changing a config file instead of code.

========================================================================
WHAT WAS DONE
========================================================================

1. Created config/surprise_rules.yaml — ONE FILE controls ALL surprise
   rule parameters. On competition day, change ONE LINE and re-run.

2. Created pi/dynamics/steering_modes.py — 4WS mode calculator with
   three modes: SAME_PHASE, OPPOSITE_PHASE (tight turns), CRAB_WALK
   (sideways parking). Switching modes takes 1 line in config.

3. Updated pi/dynamics/kinematic_model.py — Now accepts a SteeringMode
   enum and computes front/rear angles correctly for all 3 modes.

4. Updated config/pi_config.yaml — Added "surprise_rules" section
   mirroring all values from surprise_rules.yaml.

5. Updated pi/main.py — Loads surprise config at startup, prints
   the active configuration, passes steering_mode to KinematicModel.

6. Updated esp/main/l298n.c — Comments now clearly state SINGLE MOTOR
   operation (one channel for all 4 wheels), WRO Rule 11.3 compliance.

========================================================================
SURPRISE RULE SCENARIOS (how to adapt in under 60 seconds)
========================================================================

Scenario A: "Pillar colours are swapped — red means left, green means right"
  Action: Change one line in config/surprise_rules.yaml:
    pillar_logic: "REVERSED"

Scenario B: "All robots must drive counter-clockwise only"
  Action: Change one line:
    drive_direction: "CCW"

Scenario C: "Track is narrowed to minimum 600 mm"
  Action: Change one line:
    narrow_track: "ENABLED"

Scenario D: "A stop marker is placed on the track — stop for 3 seconds"
  Action: Change one line:
    stop_and_go: "ENABLED"

Scenario E: "Obstacles must be passed on the right side only"
  Action: Change one line:
    obstacle_pass_side: "RIGHT"

Scenario F: "Parking must be done in reverse orientation"
  Action: Change one line:
    parking_mode: "REVERSED"

Scenario G: "Maximum speed is limited to 1.0 m/s"
  Action: Change one line:
    max_speed_ms: 1.0

Scenario H: "Tighter turns required — use opposite-phase steering"
  Action: Change one line:
    steering_mode: "OPPOSITE_PHASE"
