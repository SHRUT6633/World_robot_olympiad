Issue 001: Logger.info() crashes with AttributeError
====================================================

Date  : 2026-07-30
Module: pi/system/logger.py (line 127)
        pi/main.py (line 182 via global_planner.plan_lap)

========================================================================
SYMPTOMS (What went wrong)
========================================================================

Command:
  $ python pi/main.py

Error:
  File "/home/shrut/wro/pi/main.py", line 182, in main
    global_planner.plan_lap(...)
  File ".../global_planner.py", line 28, in plan_rectangle
    log.info(f"Rectangle plan: {len(self.waypoints)} waypoints")
  File ".../logger.py", line 127, in info
    self.logger.info(msg, *args, **kwargs)
    ^^^^^^^^^^^
  AttributeError: 'Logger' object has no attribute 'logger'

========================================================================
ROOT CAUSE (Why it happened)
========================================================================

The Logger class is a singleton. It has TWO steps:

  Step A: Logger() creates the object          (runs at import time)
  Step B: .init()  creates self.logger inside  (must be called separately)

If you call .info() / .warn() / .error() before .init() runs,
self.logger does NOT exist yet → AttributeError crashes.

The sequence in main.py was:

  [1] from pi.system.logger import log
      → Logger() runs, object created, self.logger does NOT exist yet

  [2] ... many lines of code ...
      → log.init() is NEVER called anywhere ← THE BUG

  [3] global_planner.plan_lap(...)
      → plan_rectangle() calls log.info(...)
      → .info() tries self.logger.info(...)
      → CRASH because self.logger was never created

Think of it like a lamp:
  Logger()  = buying the lamp (it exists but does nothing)
  .init()   = plugging it in (self.logger is created)
  .info()   = turning it on (works only after plugged in)

We bought the lamp but never plugged it in → crash.

self.logger is only created in .init() (line 94), so if .init() was
never called, self.logger doesn't exist.

========================================================================
THE FIX (What I changed)
========================================================================

One line added to pi/main.py after the import:

  File: pi/main.py

   36: from pi.system.manager import SystemManager
   37: from pi.system.logger import log
   38: log.init()                                    # ✅ FIX: added here
   39: from pi.system.config_manager import ConfigManager

Why this works:
  - .init() creates self.logger = logging.getLogger("WRO_4WS")
  - .init() is idempotent: it only runs ONCE (guarded by _initialized flag)
  - From this point on, every log.info() / .warn() / .error() in any
    file (global_planner.py, manager.py, boot.py, etc.) uses the same
    self.logger that now exists

========================================================================
HOW THE FIX FLOWS THROUGH THE CODE
========================================================================

After fix, the execution chain becomes:

  main.py line 37: from pi.system.logger import log
      → Logger() creates singleton, _initialized = False

  main.py line 38: log.init()
      → singleton._initialized = True
      → singleton.logger = logging.getLogger("WRO_4WS")
        (now self.logger EXISTS)

  main.py line 56: from pi.planning.global_planner import GlobalPlanner
      → global_planner.py does: from ..system.logger import log
      → gets the SAME singleton (self.logger already exists)

  main.py line 182: global_planner.plan_lap(...)
      → plan_rectangle() calls log.info(...)
      → logger.py line 127: self.logger.info(...)  # ✅ works now

The log object in global_planner.py and main.py is the SAME object
because Logger is a singleton (controlled by __new__). So .init()
called in main.py affects the log used in global_planner.py.

========================================================================
PREVENTION (How to stop this happening again)
========================================================================

1. Every entry point (main.py, boot.py, test scripts) MUST call
   log.init() before any log message. Add it right after the import.

2. Future idea: add a lazy-init fallback in Logger so that .info()
   auto-calls .init() if self.logger is missing:
     def info(self, msg, *args, **kwargs):
         if not hasattr(self, 'logger'):
             self.init()       # auto-init if forgotten
         self.logger.info(...)
   This would make the crash impossible even if .init() is forgotten.
