Issue 003: I2C sensor errors flood console at 600 lines/second
==============================================================

Date  : 2026-07-30
Module: pi/sensors/base.py (new _log_error method)
        pi/sensors/imu/mpu6050.py
        pi/sensors/magnetometer/qmc5883l.py
        pi/sensors/tof/vl53l0x.py
        pi/sensors/tof/vl53l1x.py

========================================================================
SYMPTOMS (What went wrong)
========================================================================

Console fills with ~600 warning lines per second:

  18:50:01.237 | WARNING  | WRO_4WS | MPU6050 read error: [Errno 121] Remote I/O error
  18:50:01.238 | WARNING  | WRO_4WS | QMC5883L read error: [Errno 5] Input/output error
  18:50:01.247 | WARNING  | WRO_4WS | VL53L0X_Left: read error - [Errno 5] Input/output error
  ...
  (repeats every cycle at 100 Hz x 6 sensors)

The log file grows by ~1 MB per minute. Useful log messages are buried.

========================================================================
ROOT CAUSE (Why it happened)
========================================================================

6 I2C sensors × 100 Hz = 600 reads/second. On a robot where the
sensors are not physically connected (bench testing, partial build),
every read fails with an I2C error.

Each sensor's read_raw() method called log.warn() unconditionally on
every failure → 600 log lines/second.

The sensors were:
  - MPU6050 (IMU)        → Errno 121  (Remote I/O error)
  - QMC5883L (magnetometer) → Errno 5  (Input/output error)
  - VL53L0X Left         → Errno 5
  - VL53L0X Right        → Errno 5
  - VL53L1X Front        → Errno 5

Errno 121 = I2C slave didn't acknowledge the address.
Errno 5   = I2C bus communication failure.

Both mean the sensor is not connected, has the wrong address, or the
I2C bus is not initialised.

========================================================================
THE BROKEN CODE (before fix)
========================================================================

Every sensor's read_raw() had the same pattern:

  # mpu6050.py line 152-154:
  except Exception as e:
      log.warn(f"MPU6050 read error: {e}")   ← logs EVERY time
      return 0

  # qmc5883l.py line 163-165:
  except Exception as e:
      log.warn(f"QMC5883L read error: {e}")   ← logs EVERY time
      return np.zeros(3)

  # vl53l0x.py line 178-180:
  except Exception as e:
      log.warn(f"{self.name}: read error - {e}")   ← logs EVERY time
      return None

No rate limiting → if sensor is disconnected, it spams forever.

========================================================================
THE FIX (What I changed)
========================================================================

Two changes in pi/sensors/base.py (SensorBase):

1. Added attributes for rate limiting:

   self._last_error_log = 0.0    # timestamp of last logged error
   self._error_count = 0         # consecutive failure counter
   self._error_cooldown = 2.0    # log at most once per 2 seconds
   self._max_errors = 50         # auto-disable after 50 failures

2. Added _log_error() method:

   def _log_error(self, msg):
       now = time.monotonic()
       self._error_count += 1
       if self._error_count >= self._max_errors:  # 50 errors = 0.5 sec
           self._enabled = False                  # auto-disable sensor
       if now - self._last_error_log >= self._error_cooldown:
           self._last_error_log = now
           log.warn(f"{self.name}: {msg}")

3. In each sensor driver, replaced log.warn with self._log_error:

   # BEFORE (every cycle):
   except Exception as e:
       log.warn(f"MPU6050 read error: {e}")
       return 0

   # AFTER (rate-limited):
   except Exception as e:
       self._log_error(str(e))
       return 0

========================================================================
HOW THE FIX WORKS
========================================================================

Time  Event                        Console output
----  -----                        --------------
T0    First I2C error              "MPU6050: [Errno 121] Remote I/O error"
T1    Errors 2-39 in 0.4 sec       (silent — within 2 sec cooldown)
T2    +2 sec                       "MPU6050: [Errno 121] Remote I/O error"
T3    Error #50 (0.5 sec)          sensor._enabled = False → no more reads
T4    read() returns None silently —
                                  (no spam at all after this)

Total output: 2-3 lines instead of 600/second.
After 0.5 seconds, the sensor auto-disables completely.

========================================================================
HARDWARE NOTE (To actually FIX the I2C errors)
========================================================================

This fix only stops the SPAM. To fix the REAL problem, check:

  i2cdetect -y 1

If the sensors don't appear in the list:
  - Check wiring (VCC, GND, SDA, SCL)
  - Check I2C addresses (MPU6050=0x68, QMC5883L=0x0D,
    VL53L0X=0x29, VL53L1X=0x29)
  - Enable I2C: raspi-config → Interface Options → I2C → Enable
  - Check voltage: 3.3V sensors on 3.3V Pi pins only
